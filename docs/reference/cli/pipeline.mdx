# `nextflow pipeline`

<AddedInVersion version="27.04" />

Manage registry pipelines.

## Usage

```console
$ nextflow pipeline <subcommand> [options]
```

## Description

The `pipeline` command manages pipelines from the Nextflow registry. Use it to search the registry, view a pipeline release, and install or remove pipelines. To run a registry pipeline, use [`nextflow run`][cli-run-registry] with a registry address.

The `install`, `list`, `remove`, and `view` subcommands work on one of two stores, similar to `npm install` and `npm install -g`:

- **Project-level** (default): the `pipelines/` directory of the current folder (run it from the project root). Use it for pipelines that are [included by name][workflow-typed-registry] in another pipeline. Nextflow stores each pipeline with a `.pipeline-info` file that records the installed release. Commit installed pipelines to your project repository, as you would for vendored modules.

- **User-level** (`-g`): the directory where `nextflow run` downloads pipelines, set by [`NXF_ASSETS`][env-vars-nxf-assets] (default: `$NXF_HOME/assets`). Use it to download a pipeline ahead of a run, for example an `-offline` run, and to inspect or delete downloaded pipelines.

The `install`, `search`, and `view` subcommands use the registries defined in the [`registry`][config-registry] config scope, read from `~/.nextflow/config`, the `nextflow.config` in the current folder, and any config file given with `-c` before the subcommand.

## Options

##### `-h, -help`

Print the command usage.

## Subcommands

##### `install [options] <scope/name>` {#pipeline-install}

Install a pipeline from the registry into `pipelines/<scope>/<name>/`.
Nextflow fetches the Git commit pinned by the registry release, from the release's repository.

The following options are available:

###### `-force`

Overwrite an installed pipeline that has local modifications, or a pipeline directory without a `.pipeline-info` file. Without this flag, Nextflow refuses to replace it. Not supported with `-g`.

###### `-g, -global`

Install the pipeline into the user-level store, where `nextflow run` finds it. Nextflow resolves the release with the primary registry and downloads the Git commit pinned by the release, the same as [`nextflow pull`][cli-pull] with `-hub` set to the registry host. Use `nextflow pull` to download a pipeline that is not in the registry.

###### `-version`

Pipeline version to install, for example `3.14.0`. Defaults to the latest published release.

##### `list [options]` {#pipeline-list}

List the pipelines installed from a registry in your project.
Shows each pipeline's name, version, and status: `ok`, or `modified` if the files were changed after install.

When no pipeline is installed in the project but some are installed at the user level, Nextflow prints a hint to use `nextflow pipeline list -g`.

The following options are available:

###### `-g, -global`

List the pipelines in the user-level store, including pipelines downloaded by `nextflow run` and `nextflow pull`.

###### `-o, -output` (`text`)

Output mode for list results. Options: `text` (default), `json`.

##### `remove [options] <scope/name>` {#pipeline-remove}

Remove a pipeline from your project by deleting its `pipelines/<scope>/<name>/` directory.

The following options are available:

###### `-force`

Remove the pipeline even if it has local modifications, or has no `.pipeline-info` file because it was not installed from a registry.

###### `-g, -global`

Remove the pipeline, with all of its downloaded revisions, from the user-level store. With `-force`, Nextflow removes it even if it has local modifications.

##### `search [options] <query>` {#pipeline-search}

Search for pipelines in the registry by keyword or name.
Returns the name, latest version, and description of each matching pipeline.

The following options are available:

###### `-limit` (`20`)

Maximum number of results to return.

###### `-o, -output` (`simple`)

Output mode for search results. Options: `simple` (default), `json`.

##### `view [options] <scope/name>` {#pipeline-view}

Display detailed information about a pipeline release from the registry.
Shows the release details, the pipeline params when available, and a usage line to run it, for example `nextflow run nf-core/rnaseq -hub registry.nextflow.io -r 3.14.0`.

The following options are available:

###### `-g, -global`

Display the pipeline in the user-level store instead of the registry: its project name, repository, local path, main script, and downloaded revisions. Not supported with `-version`.

###### `-o, -output` (`text`)

Output mode for view results. Options: `text` (default), `json`.

###### `-version`

Pipeline version to query, for example `3.14.0`. Defaults to the latest published release.

## Examples

Install the latest release of a pipeline:

```console
$ nextflow pipeline install nf-core/rnaseq
```

Install a specific version, replacing local modifications:

```console
$ nextflow pipeline install nf-core/rnaseq -version 3.14.0 -force
```

Display the installed pipelines:

```console
$ nextflow pipeline list
```

Remove a pipeline:

```console
$ nextflow pipeline remove nf-core/rnaseq
```

Search for RNA-seq pipelines:

```console
$ nextflow pipeline search rnaseq
```

Search a registry configured in a separate config file:

```console
$ nextflow -c registry.config pipeline search rnaseq
```

Display information for a specific version:

```console
$ nextflow pipeline view nf-core/rnaseq -version 3.14.0
```

Download a release into the user-level store, then run it offline:

```console
$ nextflow pipeline install -g nf-core/rnaseq -version 3.14.0
$ nextflow run nf-core/rnaseq -hub registry.nextflow.io -r 3.14.0 -offline
```

List the pipelines in the user-level store:

```console
$ nextflow pipeline list -g

nextflow-io/hello
nf-core/rnaseq
```

Display the user-level copy of a pipeline:

```console
$ nextflow pipeline view -g nextflow-io/hello

  project name: nextflow-io/hello
  repository  : https://github.com/nextflow-io/hello
  local path  : /home/user/.nextflow/assets/.repos/nextflow-io/hello
  main script : main.nf
  revisions   :
  * master (default)
    mybranch
    testing
  * v1.1 [t]
    v1.2 [t]
```

Remove a pipeline from the user-level store:

```console
$ nextflow pipeline remove -g nextflow-io/hello
```
