# Migrating to 27.04

:::note
Nextflow 27.04 has not been released yet. This page describes changes on the master branch and is updated as they are merged.
:::

## New features

### Run pipelines from the registry

You can run a pipeline published in the [Nextflow registry](https://registry.nextflow.io) with `nextflow run`. Address the registry explicitly, with a registry page URL or with a registry host as `-hub`:

```bash
nextflow run https://registry.nextflow.io/pipelines/nf-core/rnaseq
nextflow run nf-core/rnaseq -hub registry.nextflow.io -r 3.14.0
```

Nextflow runs the release given with `-r`, or the latest published release, at the Git commit pinned by the release. A plain project name such as `nf-core/rnaseq` is still resolved with Git. Set `NXF_HUB` to a registry host to use the registry by default. Use `nextflow pipeline install -g` to download a registry pipeline ahead of an `-offline` run.

See [Registry pipelines][cli-run-registry] for details.

### Include pipelines from the registry

You can include a registry pipeline by its registry name, as with [pipeline composition][pipeline-composition] from a local path:

```nextflow
nextflow.enable.types = true

include { workflow as NFCORE_RNASEQ } from 'nf-core/rnaseq'
```

Nextflow installs the pipeline into `pipelines/<scope>/<name>/` when it is missing, as it does for registry modules. Commit installed pipelines to your project repository. Registry includes in an installed pipeline resolve against that pipeline's own directory.

See [Including a pipeline from the registry][workflow-typed-registry] for details.

### `pipeline` command

The new `nextflow pipeline` command manages pipelines, with the subcommands `install`, `list`, `remove`, `search`, and `view`. It mirrors the `nextflow module` command. By default, it manages the registry pipelines installed in a project.

With the `-g` (`-global`) option, the `install`, `list`, and `remove` subcommands manage the user-level store instead, like `npm -g`. This is where `nextflow run` downloads pipelines (`$NXF_ASSETS`, default: `$NXF_HOME/assets`):

```bash
nextflow pipeline install -g nf-core/rnaseq -version 3.14.0
nextflow pipeline install -g https://github.com/nextflow-io/hello
nextflow pipeline list -g
nextflow pipeline remove -g nf-core/rnaseq
```

The `pipeline` command uses the registry by default, while `nextflow run` uses GitHub by default. Give a pipeline that is not in the registry by its Git repository URL. The user-level store keeps each downloaded revision, and `pipeline list -g` prints one row for each of them. `pipeline remove -g` removes a pipeline with all of its revisions.

See [`pipeline`][cli-pipeline] for details.

## Enhancements

### Lower memory usage

The Nextflow JVM now uses the C1 compiler and the serial garbage collector by default. This reduces the CPU and memory usage for typical runs.

If you set a garbage collector in `NXF_OPTS` or `NXF_JVM_ARGS`, Nextflow uses it instead of the serial collector. To restore the previous behavior:

```bash
export NXF_OPTS="-XX:TieredStopAtLevel=4 -XX:+UseG1GC"
```

### Remove old Nextflow versions

Use `nextflow self-update -clean` to delete every installed Nextflow version except the current one. Plugins are not removed. See [`self-update`][cli-self-update-clean] for details.

## Breaking changes

- The `console` command and the `nf-console` plugin were removed.

- The `kuberun` command was removed. Use the [nf-kuberun](https://github.com/nextflow-io/nf-kuberun) plugin (`nextflow plugin nf-kuberun:run`) or launch the pipeline in a pod with Fusion instead.

- The Nextflow launcher can no longer run Nextflow versions older than 24.07.0-edge, e.g. with `NXF_VER`. To run an older version, use the launcher script from that version.

- Process [`env` inputs][process-env-inputs] are exported verbatim. Shell syntax in the value, such as `$VAR`, `$(...)`, and backticks, is no longer expanded. To reference another environment variable, set it in the task script instead. Variables in the `env` config scope are still expanded.

- Task wrapper scripts treat `$` in file names literally. Input file names that contain `${` or `$[` are rejected when they are referenced in the task script.

- Nextflow no longer opens the internal packages of the Java standard library (`java.lang`, `java.util`, `java.io`, etc.) to deep reflection. Plugins and libraries that rely on it fail with an `InaccessibleObjectException`. As a workaround, open the package named in the error with [`NXF_OPTS`][env-vars-NXF_OPTS], for example:

  ```bash
  export NXF_OPTS="--add-opens=java.base/java.util=ALL-UNNAMED"
  ```

### Cache-breaking changes

- Java types that are not [standard types][stdlib-types], such as `Optional` or `AtomicInteger`, can no longer be stored in the task cache. A task whose inputs or outputs hold such a value is not cached and re-executes when you resume, with a warning.

- Every attempt of a retried task uses the same task hash, and attempt N runs in `<hash>-N`. A retried task that previously could not be resumed re-executes once when you resume. Examples are retries that followed a work directory left over from an earlier run, and retries whose failed attempt was removed with `nextflow clean`.

## Deprecations

- The `clone`, `pull`, `drop`, `list`, and `view` commands are deprecated and hidden from `nextflow -h`. They still work, and print a warning. Use the following commands instead:

  | Deprecated | Replacement |
  |---|---|
  | `clone <project> [dir]` | `git clone <repository URL> [dir]` |
  | `pull <scope/name> -r <revision>` | `pipeline install -g <repository URL> -version <revision>`, e.g. `https://github.com/<scope/name>` |
  | `drop <project>` | `pipeline remove -g <project>` |
  | `list` | `pipeline list -g` |
  | `view <project>` | `pipeline list -g -o json` to find the local copy |

  A plain `scope/name` given to `pipeline install -g` is a registry name, so give a Git pipeline by its repository URL. The `-all`, `-hub`, `-user`, `-migrate`, and `-deep` options of `pull`, and the `-r` option of `drop`, have no equivalent: `pipeline remove -g` removes all revisions of a pipeline. A pipeline downloaded with the legacy layout holds a single revision, so `pipeline install -g` replaces its current revision and prints a warning.

- The `info` command with a project name is deprecated. Use `pipeline list -g` instead. It has no equivalent of the `-check-updates` (`-u`) option, the `-d` detail level, or the `yaml` output of `info`. `nextflow info` without a project name still prints the system information. See [Deprecations][deprecations-page] for details.
