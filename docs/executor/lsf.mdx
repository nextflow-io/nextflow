# LSF

The `lsf` executor runs pipeline tasks using a [Platform LSF](http://en.wikipedia.org/wiki/Platform_LSF) cluster. It submits each task as an LSF job using the `bsub` command.

To enable the LSF executor, set `process.executor = 'lsf'` in the `nextflow.config` file. The pipeline must be launched from a node where `bsub` is available, typically the cluster login node.

Resource requests and other job characteristics can be controlled via the following process directives:

- [clusterOptions][process-clusteroptions]
- [cpus][process-cpus]
- [memory][process-memory]
- [queue][process-queue]
- [time][process-time]

LSF supports both *per-core* and *per-job* memory limits. Nextflow assumes that LSF works in the *per-core* mode, thus it divides the requested [memory][process-memory] by the number of requested [cpus][process-cpus]. When LSF is configured to work in the *per-job* memory limit mode, you must specify this limit with the `executor.perJobMemLimit` config option. See the [Platform LSF documentation](https://www.ibm.com/support/knowledgecenter/SSETD4_9.1.3/lsf_config_ref/lsf.conf.lsb_job_memlimit.5.dita) for more information.
